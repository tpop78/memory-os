User Manual

memory-os v0.1.0

Durable working memory for AI coding agents. Your agent remembers what it's doing, how far it's got, and what's left — across context compaction and brand-new sessions — without bloating the live context window.

Claude Code plugin Node 18+ · zero deps 18 tests MIT github.com/tpop78/memory-os
The one idea: the context window is a cache, not the source of truth. Everything durable lives in .memory/ on disk. Compaction and "new session" stop being amnesia and become a cheap re-hydration from the smallest possible set of files.

01 What it gives you

  • A .memory/ contract — three markdown files that hold your plan, live state, and history.
  • Two hooks — SessionStart re-injects a bounded snapshot of where you are; PreCompact marks the journal and re-injects state so it survives summarization.
  • A skill + a command — memory-checkpoint tells the agent when/how to write back; /checkpoint flushes on demand.
  • A situational-suggestions layer — the agent proposes the right optional tool (CodeGraph, Understand-Anything, taste-skill, Firecrawl, a knowledge layer) at the right moment; you confirm.

02 Install

As a plugin (recommended):

# add the marketplace and install
/plugin marketplace add tpop78/memory-os
/plugin install memory-os@memory-os

# then, in any project you want memory in, copy the starter files:
cp -r <memory-os>/templates/.memory ./.memory

Plain (no plugin): copy the hooks block from adapters/plain/settings.json into your project's .claude/settings.json (replace <MEMORY_OS_DIR> with the absolute path to this repo), then copy templates/.memory into your project. Codex: see adapters/codex/README.md — the .memory/ files are identical; only the hook wiring differs.

03 The .memory/ contract

PLAN.md
Immutable per task. The plan, with the Definition of Done at the very top. Written once (by superpowers:writing-plans) and not rewritten as work progresses.
STATE.md
The live snapshot — overwritten, not appended. Fixed sections: Now · Definition of done · Done (n/total) · Remaining · Next action · Blockers / decisions. This is the file that gets re-injected on every session start. Keep it short.
JOURNAL.md
Append-only. One timestamped line per meaningful action. Never edit prior lines. Git history over .memory/ is your time machine.

04 How memory survives — the loop

SessionStart hook

Re-hydrate (cheap)

On startup / resume / clear / post-compaction, rehydrate.mjs injects STATE + plan pointer + recent journal lines — capped at ~6k chars. The agent wakes up knowing where it is without reading the codebase.

memory-checkpoint

Work + checkpoint

As each step completes, the agent overwrites STATE.md and appends one JOURNAL line. The disk stays ahead of the context window.

▼   context fills · compaction fires   ▼
PreCompact hook

Mark + re-inject

flush.mjs appends a ↻ compaction line to the journal and re-injects STATE as additional context, so your state survives into the post-compaction window.

→ loop closes

Resume, no loss

SessionStart fires again and the agent resumes from STATE.md's Next action. Same path covers closing your laptop and reopening tomorrow.

08 How best to use it

Do

  • Start every multi-step task by writing PLAN.md with a real Definition of Done at the top.
  • Let the agent checkpoint as it goes; run /checkpoint before anything risky.
  • Trust the re-hydration — after a compact, resume from STATE.md's Next action rather than re-reading everything.
  • Commit .memory/ often; the journal + git is your audit trail.
  • Keep STATE.md lean — it's re-injected every session under the cap.

Don't

  • Don't hand-edit JOURNAL.md history or rewrite PLAN.md mid-task — reflect progress in STATE.md.
  • Don't let STATE.md grow into an essay; it gets truncated at the cap.
  • Don't expect the PreCompact hook to capture un-written state — durability comes from continuous checkpointing by the skill, not the hook.
  • Don't commit a consuming project's live .memory/ into this repo (it's gitignored here on purpose).
